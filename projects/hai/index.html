HAI

A hybrid coding agent that learns from its own verified work, and a public record of whether it actually gets better.

See progress and runs

The question

Training intelligence is expensive. Using it doesn't have to be. Can a cheap, capable model get measurably better at coding over time without retraining, just by remembering what worked, checking that memory against reality, and improving the way it approaches problems?

Most agent memory today is notes: prose that may or may not still be true. HAI tests a different idea. Its memory is mostly code: tests, probes and checks it can run before trusting them. Anything that fails gets retired.

How it's built

Four layers. Only the harness stays fixed; everything above it is allowed to change, but only through a gate.

LayerWhat it isHow it changes
Harness fx, Vercel Labs' small, embeddable coding agent Doesn't. Kept fixed so results are comparable.
Model DeepSeek V4.1 Flash through the OpenCode API; a small local model later for weight updates Swapped only between experiments, never mid-run.
Memory Lessons from past runs plus runnable checks about each codebase, in SQLite behind an MCP server After each task, but only from runs the tests judged. Items that start failing are retired.
Strategy Prompts, skills and small tools, versioned in git An evolution agent proposes changes; they're kept only if they score better on a validation set with no regressions.

The plan

Each stage is measured against the one before it. If a stage doesn't help, that's a result, and it's recorded.

  1. Baseline. fx and the model with no memory. Establishes the starting score and how noisy runs are.
    In progress
  2. Memory. Add lessons learned from past runs. Compare against baseline on held-out tasks.
  3. Executable memory. Add tests and probes the agent can run before trusting them. Does runnable memory beat prose?
  4. Self-improving strategy. Let the agent propose changes to its own prompts and tools, keeping only those that win without breaking anything.
  5. Weight updates. Fine-tune a small local model on its own verified wins, and compare against memory alone.

How progress is measured

Tasks run as an ordered stream, so the agent can learn as it goes. Every 25 tasks, it's scored on a separate held-out set with memory frozen. Improvement there is learning; improvement only on tasks it has already seen could just be memorising.

  • Held-out pass rate: share of unseen tasks solved.
  • Regression rate: tasks that used to pass and now fail. The main check on self-improvement.
  • Steps per solved task: whether it gets more efficient, not just more accurate.
  • Memory size against use: to catch the store bloating with things it never needs.

Tasks come from public benchmarks (a Terminal-Bench and SWE-bench Pro subset) and from real repositories turned into tasks with tests.

Stopping rule, set in advance: if memory doesn't add at least 3–5 points on held-out tasks after about 200 tasks, the main idea is weak, and the layers above it won't rescue it.

Built on

  • fx for the harness
  • ReasoningBank for the shape of memory items
  • A Self-Improving Coding Agent (SICA) for the strategy loop
  • Code as Agent Harness, a survey that frames the whole approach
